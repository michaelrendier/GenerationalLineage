# Re-Pair — a sequence's own lineage tree

*`engine/toolsets/re_pair.py` · tutorial: [`examples/47_re_pair.py`](../examples/47_re_pair.py) · transcript: [`examples/transcripts/47_re_pair.txt`](../examples/transcripts/47_re_pair.txt) · added in 1.0*

**Kind of factor:** a sequence's derivation tree (repeated structure as generations).

## Definition

Re-Pair repeatedly replaces the most frequent adjacent pair with a fresh symbol. What it emits is a straight-line program: rules R → (x, y) plus a short residual start sequence. That *is* a lineage: a terminal is generation 0, a rule is 1 + the larger generation of its two children, the grammar's depth is the number of generations the sequence needs, and its size |start| + 2·|rules| is the cost of writing the sequence down through its own repeats.

## Why it belongs in the engine

It is `factor_lineage` for strings: `a` × 64 collapses to five rules of depth 5; `abracadabra` × 3 to a handful; a sequence with no repeated pair does not descend at all (no rules, depth 0).

## The two directions

| direction | what it does | cost |
|---|---|---|
| **`descend`** (free) | rules, start sequence, number of rules, depth, generation of each rule, grammar size, compression ratio, exact round trip | 0 — a single forward pass, no search |
| **`build_up`** (paid, or refused) | expand a grammar back to its sequence (cost = symbols produced); refuses a cyclic grammar | reported in `cost`; raises `AscentNotFree` (with `.owed`) when it is asked for something it cannot build from |

**Residual** (what is left when the factor is removed): the start sequence after all repeated pairs are folded.

## Guarantee and how it is checked

The round trip is exact and is checked exhaustively: every binary string of length ≤ 12 and every string over {a, b, c} of length ≤ 7 (11,471 sequences). `a` × 64 gives exactly 5 rules, depth 5, start length 2. **Minimality is NOT claimed:** finding the smallest grammar is NP-hard, Re-Pair is a greedy heuristic, and `descend` reports `minimal: None` (unknown).

**Limits, stated plainly:** Greedy and deterministic (ties broken by earliest first occurrence); the implementation is O(n²), fine for tutorial-scale input, not for megabyte inputs.

## A worked session

Every line below is the literal output of [`examples/47_re_pair.py`](../examples/47_re_pair.py), regenerated by `python3 devtools/transcript.py` and checked by the test suite; it starts from its own imports, so it can be read cold.

```text
>>> from engine.toolsets import re_pair
>>> # 64 copies of one letter need only five rules: a lineage of depth 5.
>>> r = re_pair.descend("a" * 64)
>>> r["rules"]
{'R1': ('a', 'a'), 'R2': ('R1', 'R1'), 'R3': ('R2', 'R2'), 'R4': ('R3', 'R3'), 'R5': ('R4', 'R4')}
>>> r["start"], r["n_rules"], r["depth"]
(['R5', 'R5'], 5, 5)
>>> # The round trip is exact:
>>> r["round_trip_exact"]
True
>>> # Repeated structure collapses; the grammar is far smaller than the text.
>>> p = re_pair.descend("abracadabra" * 3)
>>> p["n"], p["grammar_size"], p["depth"]
(33, 17, 7)
>>> # Symbols with no repeated pair do not descend at all.
>>> u = re_pair.descend(list(range(50)))
>>> u["n_rules"], u["depth"]
(0, 0)
>>> # Honesty: the smallest grammar is NP-hard to find, so minimality is reported as unknown, not assumed.
>>> r["minimal"] is None
True
>>> # build_up() expands a grammar back to the sequence.
>>> "".join(re_pair.build_up({"grammar": r["_grammar"]})["sequence"]) == "a" * 64
True
```
